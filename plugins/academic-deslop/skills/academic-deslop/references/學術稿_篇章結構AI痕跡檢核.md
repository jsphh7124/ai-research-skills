# 學術稿 篇章結構 AI 痕跡檢核（中英共用）

> **用途**：`academic-deslop` 的**第三層**參考。既有兩份清單（[[resources/學術英文_AI痕跡檢核清單]]、[[resources/學術中文_AI痕跡檢核清單]]）處理**詞與句**；本檔處理**段落之上**的結構痕跡——段落序列、位置分布、節奏、以及編輯流程本身的紀律。篇章結構不隨語言改變，故中英文稿共用本檔。
>
> **為什麼需要這一層**：詞句層的痕跡改寫就會消失，篇章層的不會。Russell et al. 讓專家判讀完整改寫（paraphrase）過的 AI 文章，專家在解釋判斷時提到「AI 詞彙」的比例不但沒降，反而從 69.8% 升到 88%；而且他們開始改抓引文位置（33.8% 的解釋提到引文，因為引文永遠只落在段尾）。StoryScope 在小說上得到同向結果：把故事改編過風格後，純敘事結構特徵的偵測率只從 95.5% 掉到 93.9%。只清詞句而不動結構，等於把指紋擦亮。
>
> **來源**：移植並學術校準自 [Nanako0129/sepia](https://github.com/Nanako0129/sepia) v0.4.0（MIT）的 `discourse-pass` / `professional-pass` / 校準原則。sepia 的小說路線（narrative-pass、30 特徵 rubric、五模型敘事指紋）**不移植**，理由見文末「刻意不移植的部分」。

## 第一部分：執行紀律（改動任何文字之前）

這四條管的是**怎麼清**，不是清什麼。它們的實證支撐比下面的清單條目更硬，且違反其中任何一條都會讓整個 pass 失效。

### D1 兩階段：先列完整缺陷清單，再逐項改

三條證據支持，強度不同，分開講：

**（實測）不先診斷就直接改寫，等於改寫。** Russell 等人在 300 篇文章上測過改寫（paraphrase）這條逃逸路徑，專家判讀的正確率幾乎沒有下降；更值得注意的是，專家在解釋判斷時提到 AI 詞彙的比例反而從 69.8% 升到 88%。改寫沒有移除痕跡，只是換了個位置擺。

**（實測）瓶頸在改寫不在偵測。** LAMP 的偏好排序實驗裡，讓 LLM 依人類專家標好的 oracle span 改寫，與讓它自己偵測 span 再改寫，600 筆偏好判斷的平均排名完全相同（皆 1.99；人類編輯 1.5，未編輯 2.51）。診斷做得再準，改寫功夫不到位就是救不回來——反過來說，把力氣花在「怎麼改」比花在「找得多準」划算。

**（推論）兩階段優於一次到位。** Russell 等人開發 humanizer 時試過三種做法，第一作者的質性評估認為「先讓模型依偵測指南列出所有可辨識為 AI 之處與建議修改，再依該清單逐項改」效果最好。這是開發筆記裡的主觀判斷，**不是對照實驗**。他們最後甚至放棄了事後改寫路線，理由是最大的痕跡來自生成當下而非事後沒清乾淨。

所以：兩階段值得照做，但別把它當成有實驗背書的鐵律。它真正的硬支撐是前兩條：改寫本身無效，而改寫品質才是瓶頸。

對應到我們的工作流：SKILL.md 工作流第 6 點「動檔案前先列編號變更清單」原本是為了讓使用者勾選，現在多了第二個理由。即使使用者說「直接改」，清單仍要在內部先列出來，只是不呈給他過目。

### D2 逐組分開掃

**（實測）拿到完整指南的 LLM，判讀能力接近於零，而且注意力會塌陷到單一維度。** Slop 研究把完整的標註指南交給 GPT-5、DeepSeek-V3、o3-mini，要它們判斷文本是否為 slop：與人類標註者的一致性 κ 分別是 0.01、−0.01、0.03；人類標為 slop 的比例是 35%，模型只標 3–8%。要它們抽出 slop span，字元層級 precision 在 0.13–0.16（人類標註者兩兩之間是 0.65–0.80）。最關鍵的是理由分析：o3-mini 的判斷理由**壓倒性集中在 Density 一個維度**，其餘六個維度幾乎不提，給它 in-context 範例也不改變。

**（推論）所以要一次一組。** 論文沒有測「分開掃 vs. 合併掃」，這是我們從「注意力會塌陷」推出來的對策。推論本身合理，但要知道它沒有實驗背書。

真正該記住的是那個塌陷現象：我讀完整份清單後說「來掃一遍」，最可能的結果是整份稿子只被 Density 那一把尺量過。既有清單的「快速稽核順序」本來就是分組的，照著跑，不要合併。

### D3 編輯操作比例：替換 74% / 刪除 18% / 新增 8%

LAMP 記錄 18 位 MFA 專業作家對 1,057 段 LLM 文字所做的 8,035 個編輯，操作分布為替換 74%、刪除 18%、新增 8%。

實務錨點：**在刪與補之間拿不準時，選刪不選補**。LAMP 作者在討論中引寫作界的通則「If in doubt, cut it」，並主張 overwriting 比 underwriting 嚴重得多（這是他們的立場，不是測出來的數字）。這條管的是「怎麼改」；若拿不準的是「這段到底是不是 AI 痕跡」，則不動，列進報告的「待確認」由作者判斷（見 `academic-deslop` 執行紀律 3），因為刪掉作者原文難以復原。唯一正當的「新增」是補真實的具體性：真的數字、真的文獻、真的方法細節。缺料就標「（需作者補充）」，不准填 generic 描述把篇幅撐回來。

**（實測）LLM 做編輯時的兩個系統性失敗**，正是我最容易犯的。LAMP 的質性分析指出：處理陳腔濫調時，模型「多半只是用更簡單、更少字的說法重寫，這雖然有效，卻不是人類的做法」；而在「缺乏具體性」這一類上，模型**大致上是無效的**。改到這兩類時要特別停下來檢查——它們也正好是與讀者感受到的品質相關性最高的兩類（LAMP：Awkward Word Choice 與 Cliché 的編輯次數隨品質評分上升下降最快）。

### D4 累積計分，不單點定罪

Slop 研究：標註 span 數與整體 slop 判定的 Spearman ρ 為 .63（新聞 .70、問答 .51）。AI 味是**密度現象**。單一 "crucial"、單一分詞句尾、單一三項列舉都不構成問題。

判準：同一標記在同一節出現三次以上，或不同標記在同一段落密集聚集，才動手。這條同時是誤殺的主要防線。

### D5 形狀指標不是目標

可量化的東西容易被當成成果：粗體數、三項列舉數、破折號數、diff 的紅綠比。這些是**代理指標**，優化它們會產出「看起來清乾淨了」的 diff，而真正的 AI 味原封不動。

**（實證，2026-09-01）** 一份審查意見的 deslop pass 把 inline 粗體從 37 降到 17、編號清單行從 29 降到 20，交出去被作者退回，評語是「更失真、更難讀」。同一份稿子裡「先說優點。」這種宣告式段落開場完全沒被碰到，因為它不在被優化的指標裡。同一輪還踩了兩個坑：把構念名「幽默失敗」改成指代詞「這類失敗」（失去與論文變數的對應），以及刪掉一個空殼價值詞之後補上同族的另一個（違反核心原則 6 的換湯不換藥禁令）。

判準：改完之後問「這一處刪掉，讀者少知道了什麼？」，不要問「這一輪清掉幾個標記？」。報告時列**刪了什麼、為什麼**，不列指標降幅。

**元敘述優先於形狀。** 學術稿最頑固的 AI 味是元敘述：不斷宣告「我現在要做什麼、這件事多重要」，而不把話直接講出來。典型成員：

| 類型 | 實例 | 為什麼可刪 |
|------|------|-----------|
| 宣告段落功能 | 「先說優點。」「具體建議：」「可行的補救方向：」 | 下面就是編號清單或評價本身，功能自明 |
| 預告嚴重性 | 「這裡有個技術上的硬傷：」 | 後文已經下了評價，不必先打鼓 |
| 回顧宣告 | 「如前所述」「如上面第三點所述」佔據句首 | 改成括號後置，資訊不減 |
| 空殼價值詞 | 「能大幅提升本文價值」「貢獻會精緻很多」「讓作者心裡有底」 | 通不過抽主詞測試 |
| 冗餘立場標記 | 逐句「我認為」（整份稿子本來就是作者的判斷） | 保留少數幾處即可 |

這一族**一律純刪**：刪掉之後一個資訊點都不會少，所以不需要替換，也就沒有換湯不換藥的空間。可程式化自檢：清理後的文字必須是原文的**子序列**（只刪不加）。

```python
def is_subseq(new, old):          # new 可否由 old 只刪不加得到
    it = iter(old)
    return all(ch in it for ch in new)
```

## 第二部分：篇章結構痕跡

### P1 段落問題序列（QUD 檢查）— 學術版

**（實測）LLM 重複使用篇章結構，而且彼此像得超過像人。** QUDsim 的做法是把每個段落還原成它隱含回答的那個問題，再比對兩份文件的問題序列。結果：同一個模型拿到內容不同的題目，產出的結構高度雷同；不同模型之間的結構相似度，**高於兩位人類作者為兩個不同的人寫訃聞時的相似度**。案例分析裡，Gemini 與 GPT-4o 拿到不同提示，仍各自寫出「被告知秘密 → 解釋為何要維持這個謊 → 談後果 → 反思責任的重量」這同一條線。

> ⚠️ **一處必須更正的歸因**。sepia 的研究帳本把「LLM 使用後果／程序型段落約 19%，比較／查核型僅 0.2–0.3%」當成人機對比數據，我第一版照抄了。核對原文後確認：那是論文 Table 9，**全資料集 601 個 QUD 的類型分布，人類與 LLM 混在一起沒有分開**（Concept 37.1%、Example 28.1%、Consequence 10.0%、Procedural 9.8%…Verification 0.3%、Comparison 0.2%）。論文從未報告依來源分開的 move type 頻率。所以「缺少比較與質疑段是 AI 味」這個推論**沒有實證基礎**——人類寫的訃聞同樣很少用這兩種 move。

**（外推）真正可用的是什麼**：學術稿的段落序列**本來就受格式規範**（IMRaD、文獻回顧的構念→研究史→缺口），所以「序列規整」在學術稿**不是**痕跡，不要照 sepia 的原意去打亂它。QUD 抽取值得留下來，但改個用途——不是拿來抓 AI，是拿來抓論證缺陷：

| 檢查 | 該有什麼 | 缺席代表什麼 |
|------|---------|------------|
| **比較 move** | 至少一段在對照兩個理論／兩派發現／兩個測量取向，並指出它們互不相容之處 | 文獻回顧變成「誰誰誰發現了什麼」的流水帳。這是 AI 生成文獻回顧最一致的破綻，也**恰好是審稿人最常抱怨的實質缺點** |
| **查核 move** | 至少一段在質疑前面剛講過的東西（「然而，這個解釋無法說明…」「Smith 的結果建立在 X 假設上，而該假設在 Y 情境不成立」） | 每段都在累加、沒有一段在減損。人寫的文獻回顧必然有內部張力 |
| **後果 move 過載** | — | 連續數段都是「因此…」「這導致…」的推進，沒有停下來比較或懷疑 |

**操作**：把文獻回顧或 Discussion 的每一段濃縮成「這段在回答什麼問題」，列成一欄。若整欄沒有任何一個問題是**比較性**或**質疑性**的，回報使用者，但**當成論證缺陷提，不要當成 AI 痕跡提**——一份沒有任何對照與質疑的文獻回顧，不管誰寫的都會被審稿人抓，而這正是它值得修的理由。

至於 QUDsim 那個真正測到的結果（結構重用、模型彼此相像），在學術稿上的對應症狀是：**同一份稿子裡每個文獻回顧段的形狀都一樣**（介紹構念 → 誰研究過 → 發現什麼 → 但仍有不足），一段接一段複製。這個可以當痕跡看，因為它是「重用同一個模板」而非「缺少某種 move」。

### P2 首句抽取測試（Outline test）— 學術版需反轉

**原始規則**：抽出每段第一句排成清單，若讀起來是一份乾淨的摘要，結構就是機器形狀（人寫的大綱有跳躍與斷裂）。

**⚠️ 這條在學術稿不能照用（外推）**：學術散文要求 topic sentence，首句串起來像摘要**是正確的**，不是痕跡。照搬會把好文章改壞。

**學術版改法**，抽完首句後檢查三件事：

1. **有沒有任何一句帶轉折**（However / In contrast / 然而 / 相對地）。全部是累加式（Moreover / Additionally / 此外 / 再者），是機器形狀。
2. **有沒有段落首句只是重述該節標題**（對應英文清單 #29、中文清單相應條目）。
3. **首句長度是否全部落在同一區間**。人寫的段落有長有短，會有一段以極短句開場。

### P3 中段是弱點（Chokepoint）

**（實測）自動偵測器在正文中段最容易識破 AI 文字。** Chokepoints 用五個偵測器（GPTZero、MAGE、Radar、Binoculars、GPT-Who）測路透新聞、美國中學論說文、Enron 電郵：**中段的偽陰性率（把 AI 誤判為人）在所有領域都最低**，且中段單獨拿去測的表現勝過開頭加結尾兩者相加。Integrated Gradients 的 token 貢獻分析也指向中段。

有一個容易誤讀的轉折要講清楚：在未控制長度的原始設定下，中段其實顯示出**較小**的人機差異，因為它比較長，把 POS 分布、情感、正式度這類特徵平均掉了。**控制長度之後才反轉**，中段變成差異最大的一段。所以「中段最露餡」成立，但成立的條件是逐段等量比較。

> 註：我第一版寫「偵測器與人類判讀者都在中段最容易識破」，人類判讀者那半句是我加的，這篇論文沒測人類判讀。

**（實測）人類作者的跨段變異大於 AI。** 同一篇文章的開頭、中段、結尾之間，人類的語言指紋會明顯變動，AI 則維持均勻——LLM 傾向產出界線分明、轉場平滑、內容與詞性分布均勻的三段式。

**（外推）學術轉譯**：學術稿的頭尾（Abstract、Introduction 開場、Conclusion）是作者反覆打磨、共同作者也會看的地方；文獻回顧中段與 Discussion 中段是最少人細讀的地方。這裡機制上加成——AI 本來就在中段最弱，人類把關本來就在中段最鬆。注意這篇的模型是 2023 世代（GPT-3.5、PaLM、LLaMA2-7B、Mistral-7B），新模型的中段是否同樣弱，沒有證據。

**操作**：稽核**從中段開始**，不要從第一頁開始順著讀。把時間預算的一半放在文獻回顧第 2/4 到 3/4 段、以及 Discussion 講完主要發現之後、講到限制之前的那幾段。

### P4 位置指紋（改寫殺不掉的那一層）

**（實測）改寫過的文章，專家改抓位置。** Russell 等人的專家在解釋為何判定改寫版文章是 AI 寫的時，有 33.8% 的解釋提到**引文**，遠高於其他任何實驗條件。原因寫得很清楚：專家發現引文「永遠是同一個格式與樣式，例如一律只擺在每段最後」。這是位置指紋在改寫後不減反增的直接證據。

其餘幾列的證據強度不同，逐條標示：

| 位置指紋 | 機器習慣 | 人類習慣 | 學術稿判準 |
|---------|---------|---------|-----------|
| **引文位置**（實測） | 固定在段尾 | 散布，含句中與句首 | 檢查連續段落的引文是否都落在最後一句。學術寫作可以且應該有 "Smith (2020) argued that…" 開場的句子 |
| **段落長度**（實測，Chokepoints 的跨段均勻性） | 均一 | 參差，含明顯偏短的段落 | 重要的貢獻給兩倍篇幅，次要的一段話帶過。全篇每段都 5–7 句是機器節拍器 |
| **列舉項數**（實測：Russell 的專家中有兩位專門抓「LLM 舉例永遠三個一組」） | 恰好三項，處處如此 | 二、四、一都有 | 真有三個構念就三項；為對稱而湊的第三項刪掉 |
| 段落轉場（推論） | 每段用同一族連接詞 | 有硬切、有承接、有對比 | 全篇 Moreover / Furthermore / 此外 反覆出現即為訊號 |
| 強調分布（推論） | 平均散開 | 集中在要緊處，其餘從缺 | 每節都恰好粗體一個詞、每節都恰好一個「值得注意的是」，是模板 |

### P5 分形摘要（Fractal summary）

**症狀**（推論；來自維基百科「Signs of AI writing」的編輯經驗清單，非量測）：每個層級都「預告 → 講 → 回顧」。第 2 節開頭說本節將討論三件事，中間討論，結尾說本節討論了三件事；每個小節也各自這樣做一次。

**學術校準**：章節層級的 roadmap 是**正當**的（英文清單 B 區 #28、中文清單 B 區 #36 已豁免），結論章的收束也是**必須**的（中文清單 C 區）。要清的是**中間層級的重複**——小節結尾的「這意味著…」、次小節開頭的「如前所述…」。

判準：同一個資訊在同一份稿件裡被講述**三次以上**（預告一次、正文一次、回顧一次，再加上摘要或結論），刪掉中間層那次。

### P6 場域校準（Venue corpus）— 比通用「人味」更準的靶

**（實測）這是本檔證據最硬的一條，而且直接測在學術寫作上。** Reinhart 等人的結論是：instruction tuning 把模型鎖進一種名詞密集、資訊密度高的固定文風，**即使被要求配合其他語域也調不動**；他們的 significance statement 明講這種錯位發生在「academic writing、互動口語、新聞」這些有明確慣例的文類上。更關鍵的是他們對詞彙問題的詮釋：

> 重點不在於人類不用這些詞，而在於人類不會**在這些文類裡**用這些詞。在小說裡不起眼的字，用到別的文類就格外顯眼。

也就是說，AI 味的很大一部分根本不是「不像人」，是「不像這個場域的人」。那麼校準的靶就不該是抽象的「人味」，而是目標期刊本身。

**操作（外推，但成本低效益高）**：動筆前取目標期刊近三年 2–3 篇同類型論文（同樣是實證文、同樣的方法取向），比對三件事：

1. **句長與段長的實際分布**：AMJ 的 Discussion 與 JAP 的 Discussion 節奏不同，中文的《管理學報》《臺大管理論叢》又是另一種。
2. **第一人稱的使用密度**："We argue" 在有些期刊滿頁都是，有些幾乎不見；中文稿的「本研究／本文／筆者」比例同理。
3. **文獻回顧的段落長度慣例與引文密度**。

沒有可比對的樣本時（例如聊天中貼上的片段），退回既有清單的預設值即可，並在「待確認」註明未做場域校準。

### P7 過度校正也是指紋（Over-correction）

核心原則：**瞄準人類的分布區間，不要瞄準 AI 的反面**。人類的數值多落在中間；把每條規則都推到極端，會製造出另一種可辨識的指紋。

**（實測）兩個直接證據。** 其一，Russell 研究中判讀最差的那群非專家，錯誤正是來自反向推理：他們以為文法完美代表人寫的（事實相反，人類的文法錯誤更多）、以為中性語氣代表 AI（這是他們偽陽性的主因）、以為用了冷僻字就是 AI（專家抓的是特定的一批詞，不是「高級詞」）。其二，o1-pro 生成的文章大量使用縮寫與口語，確實騙倒了其中一位標註者，但專家群體的多數決仍然 100% 正確——**加口語不是偽裝**，它只是換掉一個維度，其餘維度照樣露餡。

學術稿最容易發生的四種過度校正：

| 過度校正 | 後果 | 正確的落點 |
|---------|------|-----------|
| 把 hedging 清光 | 「本研究證明 X 導致 Y」——橫斷面資料寫成因果宣稱，審稿人第一輪就退 | 單層 hedging 保留（英文清單 B 區 #24、中文 B 區 #33） |
| 刻意打亂句長 | 讀起來像刻意做作，且違反學術散文的可讀性要求 | 節奏跟著論證走：核心論證處鋪長句，過場處短 |
| 拒絕 signposting | 讀者迷路，審稿人抱怨結構不清 | 章節層級的指路保留 |
| 為了「有立場」而代作者下判斷 | 誠信問題，比 AI 味嚴重得多 | 標「（需作者補充立場）」，不代寫 |

**報告義務**：偵測到自己可能過度校正時，在產出的「保留項說明」中單獨列出，標為過度校正警示，不要當成 AI 痕跡處理掉。

**Dash 規則屬於本節**：dash 規則是**密度規則**，不是零容忍。單一個 em-dash 不構成訊號，偶爾使用可以接受；要清的是「一頁裡連下好幾個」。這與本檔 D4「累積才算數」同源，不是例外。

機械把 em-dash 清到零，正是本節講的過度校正——刻意零 dash 的稿子讀起來與刻意亂化句長一樣不自然。配額（同段一個、同頁一個、不要每頁都有）與超額時的取捨判準見兩份詞句層清單的硬規則區塊。

## 第三部分：誤判白名單（學術稿版）

過度校正的第一道防線。以下**不是** AI 證據，不得據以修改：

| 不要標記 | 理由 |
|---------|------|
| 文法乾淨、標點正確 | **人類的文法錯誤比 AI 多**（Russell 的專家明確以此判讀，非專家搞反了方向才失準）。刻意植入不完美是可偵測的把戲，在學術稿更是負分 |
| 中性或正式語氣 | **非專家最大的偽陽性來源就是「語氣中性 = AI」**。期刊就是正式語域，配合語域勝過強行口語化。學術稿完全不適用「加口語詞」那套：Reinhart 的不足構式清單裡的縮寫、髒話、discourse particles、句首 well/anyway，在學術散文本來就不該有 |
| 用字典雅 | 非專家把任何冷僻或華麗的字當成 AI 證據；專家抓的是**特定的一批詞**（testament、crucial 那一類），不是「難字」本身 |
| 單一標記出現一次 | 見 D4，累積才算 |
| 引號內、量表題項內、受訪者原話內的任何用語 | 逐字保留，即使本身很有 AI 味 |
| 期刊格式要求的結構 | 摘要的固定段落、關鍵詞、Limitations 段、資料可得性聲明，都是慣例容器 |
| 真正可枚舉的條列 | 三個假設就是三項，不必為了「破除三項列舉」硬拆 |
| 作者本人已驗證的習慣 | 作者慣用的句法就是作者的 voice，對照作者既有的寫作樣本 |

Reinhart 的「不足構式」裡有**少數**在學術散文正當可用，值得反向補。以下括號內為 GPT-4o 相對人類的使用率（附錄 Table 3，已逐格核對；Llama 3 的 base 版本這些數值都接近 100%，可見偏差來自 instruction tuning 而非訓練語料）：

- **because**（20%）：學術散文完全可以用 because，不必每次都改成 "due to the fact that" 或名詞化。
- **synthetic negation**（51%）：「no existing account explains…」比「existing accounts fail to explain…」更有力，也更省字。
- **demonstrative pronouns**（50%）與 **that-deletion**（66%）：正常學術英文用得到；"we argue [that] X" 的 that 可省。
- **wh-questions**（56%）：研究問題本來就是問句，Introduction 可以直接問。

其餘（縮寫 60%、amplifiers 46%、discourse particles 60%、第二人稱 52%）在學術稿一律**不補**：它們用量低是因為語域不合，不是缺陷。
