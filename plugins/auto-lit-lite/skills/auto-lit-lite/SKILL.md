# auto-lit-lite — 文獻通知掃描與免費管道下載

依使用者指定的條件掃描期刊通知信 → 產出候選清單 → 使用者勾選 → 經免費公開管道下載 PDF 並以規則命名入庫。

## 設計定位與授權邊界（先讀）

- 本技能只用**免費且公開**的取得管道——出版商 OA、機構典藏、作者自存檔、arXiv。不需要任何付費會員；不繞過付費牆、不代填驗證碼、不用盜版鏡像站。付費牆內拿不到的文獻，誠實標「需手動」，由使用者走機構圖書館。
- **「抓得到」不等於「授權無虞」**：作者自存檔（ResearchGate、機構典藏）的授權狀態由上傳者負責；下載僅供使用者**個人研究使用，不再散布**。
- 在校園網路內（或 Google 帳號帶機構身分時），Scholar 會顯示機構訂閱的直連——這些屬**機構授權範圍內的個人使用**，但多數機構授權**禁止系統性、大量的自動化下載**：維持小批次（一次任務數篇到數十篇）、遵守節流，並以你機構的授權條款為準。
- Google Scholar 對自動化查詢敏感：本技能只做**低頻互動式**查詢（一次任務內逐篇、間隔 ≥10 秒），出現驗證碼即停、由使用者本人處理。要做大規模系統性檢索，請改用 OpenAlex／CrossRef 等開放 API，不要用 Scholar。

## 首次使用設定

| 設定 | 說明 |
|---|---|
| gog CLI | Gmail 掃描工具。安裝與授權見**同一 marketplace 的 `gogcli` skill**（`/plugin install gogcli@ai-research-skills`），完成 `gog auth login` |
| Gmail 標籤 | 建「Journal TOC」標籤＋篩選器聚合 TOC 信；建「AI已閱讀」標籤標記已掃描信件（名稱可自訂） |
| 瀏覽器（下載時） | Claude Code 搭配 Claude in Chrome 擴充功能（以 `claude --chrome` 啟動 session；安裝見官方文件）。純掃描不需要 |
| Unpaywall email | 查 OA 副本時 API 要求提供真實聯絡 email；首次用到時問使用者並記入 `status.md` 開頭 |
| `status.md` | 已下載清單與待辦，放在使用者的文獻專案目錄（格式見下） |
| `preferences.md` | 閱讀偏好紀錄，供相關度評星校準；可從空檔開始累積（格式見下） |

**`status.md` 最小格式**（每行一篇，倒序追加；下例為虛構示範。無 DOI 的文獻用 arXiv id 或「作者+年+標題前綴」當唯一鍵）：

```
## 已下載
- 2026-08-13 | 10.1037/apl0001234 | Hickman et al. (25) Automated speech recognition bias… | 管道: Scholar直連
## 待辦
- [ ] Smith (24) Some paper — 需手動（無 OA 副本），館際申請
```

**`preferences.md` 最小格式**：

```
## 已確認偏好（使用者明講或多次驗證）
- 對「量表建構／測量方法」類永遠有興趣，即使主題不直接相關
## 偏好假設（待驗證）
- 疑似對純宏觀策略類無興趣（2 次未勾）
## 各輪紀錄
- 2026-08-13：呈 20 篇勾 8；漏抓 1（使用者自行撈回：方法類）→ 判準太窄
```

## 步驟 0｜解析請求

從使用者的話拆出兩要素，缺一則問：

1. **主題詞**（如 overqualification、algorithmic management）；「全部新文章」也是合法答案
2. **時間範圍**（發表年份，與／或「最近 N 個月」的通知期間）。注意：Gmail 只能篩**通知信日期**，發表年份要在逐篇解析時另行過濾。

## 步驟 1｜掃描 Gmail 通知信

依 `references/source-gmail.md` 執行：組 query（標籤＋時間；主題預篩僅限使用者明確給定狹窄主題時）→ 逐信解析 → **解析結果先落地清單，再套已閱讀標籤**。命中的信全數「解析入清單或明確排除」且已套標，此步才算完成。

## 步驟 2｜候選清單 → 使用者勾選

1. 合併結果、去重（同 DOI／同標題視為同篇）。
2. 與 `status.md` 的已下載清單比對，剔除已下載者。
3. **評相關度前先讀 `preferences.md`**：據其歷次勾選紀錄校準星等——使用者的興趣圈往往比「主題直接命中」寬（方法工具、量表建構、鄰近構念都可能在圈內）。**收尾時回寫該檔**：本輪勾選率、使用者撈回的遺漏（＝判準太窄的證據）、高星未選項（＝判準太鬆的證據）。
4. 呈清單給使用者勾選，每篇標：**作者、標題、期刊、年份、預計下載管道（免費直連 / OA / RG / 需手動）、與主題的相關度、一句話摘要**。摘要以通知信所附摘要／標題為依據，濃縮成一句可讀的白話描述（研究問題＋主要發現或貢獻）。
5. **通知信只有標題時，主動補抓 abstract**：優先序 ①`doi.org/<DOI>` 或期刊官網文章頁（WebFetch 通常可直取，不需瀏覽器）②ResearchGate 頁面 ③CrossRef metadata 的 abstract 欄位（JATS/XML 標籤要剝除再用）。仍取不到才標「僅標題可判」，不腦補。

## 步驟 3｜下載與命名

依 `references/download-free.md` 逐篇走免費管道階梯，檔名一律照 `references/naming-rules.md`。

節流原則：批次下載每篇間隔 ≥1.5 秒；同 domain 不並行；Scholar 連續查詢間隔 ≥10 秒。

**完成標準**：每篇勾選文獻「以規則檔名落地於下載目錄」或「標註需手動＋原因（paywall / 無 OA 副本 / 連結失效 / 授權不明）」，且 `status.md` 的已下載清單已更新（含 DOI）。少一篇都不算完。

## 收尾

- **複審迴圈（校準期建議常設）**：下載批次完成後，主動提供「未入選」的複審清單（編號可勾選；使用者點名要進一步資訊的補抓完整摘要）。這是刻意的雙重把關——訓練偏好模型＋人工防遺漏；複審結果照常回寫 `preferences.md`。
- ⚠️ **Dialogue／延伸／回覆類文章的清單描述必須寫明「被延伸文章的主題領域」**：這類文章的主旨由母文決定，描述時母文領域優先於延伸角度，否則使用者容易據延伸角度誤選。
- ⚠️ **書評／短評偵測**：①欄目前綴不可全信（有的期刊書評無標記），essay／評論嫌疑者在摘要補抓時順看文章頁的欄目標籤；②下載後 PDF 體積異常小（如 <100KB）是**弱訊號**——僅供示警提醒使用者確認，不當判準。
- 更新 `status.md`：已下載清單追加本批、待辦勾銷。
- 跑出新的穩定 SOP（如某出版商 OA 頁的抓法）→ 回寫進**你本機安裝的** `download-free.md` 副本，讓下次直接照做（是個人化你的本機副本，不是修改共享 repo）。

## 隱私邊界

`status.md`／`preferences.md` 只記書目資訊（DOI、作者、標題、期刊、年份）與偏好判斷；**不保存**信件全文、寄件者、message id、下載 URL token 等內容。`preferences.md` 記錄的是使用者的研究興趣軌跡，屬敏感的個人研究資料——留在使用者本機專案目錄，不上傳、不放進共享 repo。
